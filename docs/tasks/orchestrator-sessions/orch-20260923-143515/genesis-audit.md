# Genesis: interface and brand audit

## Objective
Identify exact student-facing surfaces and brand touchpoints affected by the approved Margin rebrand; produce a safe implementation map that protects unrelated work.

## Scope
Read marketing, auth, dashboard shell, builder creation and writing workspace component hierarchy; inspect theme, CSS, fonts, metadata, manifest and design docs. List high-impact hard-coded styles and visible brand strings. Do not change production files, APIs, billing or data.

## Definition of done
A concise component map and risks are recorded; production edits are limited to agreed surfaces; existing dirty files are identified and preserved.

## Expected artifacts
Audit notes in the orchestration session or the delegated response, feeding `docs/features/Margin_Rebrand.md` and `docs/walkthroughs/margin_rebrand.md`.

## Instructions
Read-only analysis. Distinguish active screens from legacy variants. Suggest the smallest set of changes that delivers one coherent rebrand. Do not recommend blanket search-and-replace of billing, transactional data, route names, or model prompts.
